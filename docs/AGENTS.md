# Design-document guidance

Follow `docs/contracts/documentation.md`.

- Preserve the authority and purpose of each document.
- Do not write a proposed mechanic into `game-rules.md` until it is deliberately accepted.
- Never rewrite decision history; append a superseding decision.
- Keep plans and prototype status in `vertical-slices.md`, not in permanent rule truth.
- Keep observations in `playtest-log.md`; label inference and proposed response explicitly.
- Prefer concrete player-facing language over implementation terminology in rules.
